# Basketball CV

Программа для **автоматизированного анализа баскетбольного матча по видео** на основе методов компьютерного зрения.

Основной сценарий: пользователь загружает запись матча, при желании задаёт названия команд и составы, после чего система автоматически формирует размеченное видео, игровые события и статистику. Ручная разметка площадки и ручная коррекция результатов не входят в основной интерфейс.

## Что определяет система

- игроков и их треки;
- две команды по визуальным признакам формы;
- номера на майках и, если задан состав, имена игроков;
- мяч, кольца и ключевые точки площадки;
- судей отдельным классом `REFEREE` без включения их в статистику игроков;
- владение мячом;
- броски, попадания/промахи, передачи, ассисты, перехваты, потери, подборы и блок-шоты;
- счёт по найденным попаданиям;
- скорость, дистанцию, время владения и box score;
- shot chart и heatmap.

## Интерфейс

В приложении две вкладки:

1. **Анализ** — загрузка видео, необязательные названия/составы и запуск.
2. **Результаты** — обработанное видео, статистика команд/игроков, автоматически найденные события, shot chart, heatmap и ZIP результата.

Основные значения по умолчанию:

- tracker: **SAM2**;
- классификация команд: **PCA**;
- альтернативный метод для эксперимента: **UMAP**;
- чтение номеров: **ResNet** при наличии готовых весов, иначе SmolVLM2;
- длительность: `0` — всё видео;
- тяжёлый анализ: **30 FPS**;
- итоговое видео: до **30 FPS**.

Разделение FPS сделано специально: нейросетевой анализ не обязан запускаться на каждом кадре, но выходное видео остаётся плавным.

## Автоматическая площадка

Основной режим использует модель ключевых точек площадки и гомографию. Пользователь не ставит точки вручную.

Если автоматическая калибровка не сработала, остальные части анализа продолжают работу, а метрики, требующие координат в метрах, становятся недоступны. Причина отображается в блоке **Диагностика**.

Ручная калибровка сохранена внутри библиотеки только как служебный инструмент для разработки/оценки и не показывается пользователю.

## Игроки и номера

Состав команды — это необязательный справочник:

```text
0 Tatum
7 Brown
11 Pritchard
```

Система сначала сама распознаёт номер на видео, а затем связывает его с именем из состава. Если состав не задан, на видео остаётся только номер. Если номер не удалось подтвердить — используется ID трека.

### Готовые веса ResNet

Рабочий файл называется:

```text
models/jersey_resnet.pt
```

Он **не входит в ZIP и Git-репозиторий**, потому что весит около 82 МБ. Наши обученные веса опубликованы как asset GitHub Release `models` и в Colab скачиваются автоматически напрямую с GitHub в `models/jersey_resnet.pt`.

При обычном запуске модель **не переобучается**. Bootstrap ищет веса в таком порядке:

1. `models/jersey_resnet.pt`;
2. путь из `JERSEY_RESNET_PATH`;
3. URL из `JERSEY_RESNET_URL` или `--jersey-url`;
4. встроенная ссылка на наш публичный GitHub Release.

`models/jersey_resnet_report.json` остаётся в репозитории как отчёт обучения. Скрипты обучения сохранены только для воспроизводимости эксперимента.

## PCA и UMAP

Оба метода реализованы и доступны в интерфейсе:

- **PCA** — основной: быстрый, воспроизводимый, мало зависимостей;
- **UMAP** — альтернативный: используется для сравнения качества кластеризации команд.

## Судьи

Roboflow-детектор имеет класс `referee`. Судьи:

- рисуются отдельной рамкой `REFEREE`;
- не попадают в команды, владение и статистику игроков;
- при валидной гомографии фильтруются по положению относительно площадки, чтобы уменьшить ложные срабатывания на персонал у скамейки.

## Баннеры событий

На видео используются короткие ASCII-подписи, совместимые с OpenCV:

```text
3PT MADE | #8
MISS | #25
PASS | #11 -> #2
ASSIST | #2 -> #8
STEAL | #9
TURNOVER | #11
REBOUND | #25
BLOCK | #42
```

Скорость игрока (`km/h`) остаётся рядом с его подписью.

## Быстрый запуск в Google Colab

Используйте `Basketball_CV_Colab.ipynb`. В нём оставлены только **три ячейки**:

1. загрузка `basketball-cv.zip`;
2. автоматическая подготовка окружения, SAM2 и ResNet;
3. запуск интерфейса.

В Colab Secrets нужен только:

```text
ROBOFLOW_API_KEY
```

Для ResNet отдельный Secret больше не нужен: наши веса скачиваются из GitHub Release автоматически. `JERSEY_RESNET_URL` остаётся только как необязательный способ заменить источник весов.

### Почему установка стала быстрее

Colab уже содержит Python, CUDA, PyTorch, NumPy, OpenCV и другие научные библиотеки. Быстрый установщик `scripts/bootstrap_colab.py`:

- использует системный Python/PyTorch Colab для основного приложения; Python 3.12 скачивается только для Roboflow-worker, если сам Colab уже на Python 3.13;
- **не устанавливает второй PyTorch для основного приложения**;
- проверяет пакеты и ставит только отсутствующие/несовместимые;
- создаёт окружение Roboflow с `system-site-packages`, чтобы по возможности переиспользовать уже загруженный PyTorch Colab;
- не компилирует CUDA-расширение SAM2 — исходники подключаются напрямую;
- не повторяет установку и загрузку моделей при повторном запуске в той же Colab-сессии.

Если будущий образ Colab окажется несовместим с быстрым окружением Roboflow, установщик автоматически переключится на более медленный изолированный вариант вместо того, чтобы сломать запуск.

## Локальный запуск

Для локального компьютера остаётся воспроизводимое изолированное окружение. Рекомендуемый Python 3.11/3.12:

```bash
python scripts/bootstrap.py --device cuda --roboflow --sam2
.venv/bin/python -m basketball_cv.cli ui
```

Windows после bootstrap:

```bat
.venv\Scripts\python.exe -m basketball_cv.cli ui
```

Для CPU:

```bash
python scripts/bootstrap.py --device cpu --roboflow
```

## Результаты

Каждый запуск создаёт `outputs/run-*` с файлами:

- `annotated.mp4`;
- `players.csv`;
- `teams.csv`;
- `events.csv` / `events.json`;
- `tracks.csv` / `tracks_summary.csv`;
- `summary.json`;
- `shot_chart.png`;
- `heatmap.png`;
- `report.html`;
- `results.zip`.

Автоматические события имеют статус `automatic`. Ручная разметка, если она понадобится для расчёта Precision/Recall/F1, должна создаваться отдельно как **ground truth** и не изменять результат программы.

## Эксперименты для диплома

Проект оставляет альтернативы специально для сравнительной главы:

- SAM2 vs ByteTrack;
- PCA vs UMAP;
- ResNet vs SmolVLM2;
- 10/15/20/30 FPS анализа.

Сравнивать стоит по точности событий/идентификации, фрагментации треков и времени обработки.

### Выбор детектора Roboflow

В интерфейсе доступны три варианта одной баскетбольной модели для A/B-проверки на реальных видео:

- `basketball-player-detection-3-ycjdo/13` — RF-DETR Medium, основной вариант;
- `basketball-player-detection-3-ycjdo/18` — RF-DETR NAS, экспериментальный вариант;
- `basketball-player-detection-3-ycjdo/4` — старый YOLOv11s, сохранён как базовая линия для сравнения.

Для честного сравнения используйте один и тот же ролик и одинаковые FPS анализа, трекер и порог уверенности.
В результатах фактически использованный `model_id` записывается в `summary.json` и показывается в диагностике интерфейса.
