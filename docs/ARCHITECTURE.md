# Архитектура

```
видео
 │
 ├─ [1] восприятие ─ .venv-rf: perception_worker.py (модели Roboflow)
 │        детектор игроков/мяча/кольца/номеров + ключевые точки площадки + чтение номеров
 │        → outputs/_cache/perception-<ключ>.jsonl   (кэш: инференс один раз)
 │
 ├─ [2] команды ─ teams.py: выборка кадров → эмбеддинги (SigLIP или цвет) → PCA → K-means(2)
 │
 ├─ [3] проход анализа (видео не рисуется) ─ pipeline.py
 │        detectors: ByteTrack локально ИЛИ треки SAM2 из восприятия → треки
 │        geometry.KeypointCourtMapper                 → гомография кадр→метры
 │        analytics.BallSelector / Possession / Motion  → мяч, владелец, скорость, путь
 │        identity.JerseyNumberAssigner                → номер трека
 │        events.EventEngine (+ ShotTracker)            → броски, очки, потери, подборы…
 │        drawing                                       → видео с разметкой и мини-картой
 │
 ├─ [4] номера ─ второй вызов моделей Roboflow только на выбранных кропах
 │        identity.select_number_crops: 6-12 лучших рамок на игрока вместо тысяч подряд
 │
 ├─ [5] постобработка
          identity.match_clusters_to_teams  → какой кластер какая команда
          boxscore.build_boxscore           → объединение треков в игроков, статистика
          report.make_report                → HTML, CSV, JSON, ZIP
 │
 └─ [6] проход отрисовки ─ render_video
          подписи «#8 Имя», цвета команд и табло со счётом верны с первого кадра
```

## Модули

| Модуль | Ответственность |
|---|---|
| `court.py` | Размеры NBA/FIBA, 33 опорные точки в порядке модели `basketball-court-detection-2`, правило трёх очков, зона штрафного |
| `frames.py` | Единый выбор кадров (стride, фрагмент, масштаб) для приложения и воркера |
| `perception_worker.py` | Запуск моделей Roboflow в изолированном окружении, запись JSONL |
| `perception.py` | Чтение кэша, запуск воркера, ключ кэша по параметрам |
| `detectors.py` | Формат `Detection`, отображение классов, YOLO, Roboflow API, ByteTrack, приём треков SAM2 |
| `geometry.py` | Гомография по ключевым точкам (RANSAC, сглаживание, контроль ошибки), ручной режим, детектор склеек |
| `teams.py` | Эмбеддинги, кластеризация, голосование по трекам |
| `identity.py` | Номер → трек (IoS + голосование), составы, сопоставление кластеров с командами |
| `jersey.py` | ResNet-классификатор номеров: подготовка кропов, инференс пачками |
| `analytics.py` | Выбор мяча, владение как состояние (окно памяти, гистерезис), скорость и дистанция |
| `events.py` | Автомат броска: сохранение точки выпуска, устойчивое прохождение мяча через кольцо, очки, перехват/потеря/подбор/передача/блок |
| `boxscore.py` | Объединение треков в игроков, статистика игроков и команд |
| `drawing.py` | Площадка, тепловая карта, карта бросков, мини-карта |
| `report.py` | CSV/JSON, HTML-отчёт, ZIP, пересчёт после пользовательской коррекции |
| `evaluation.py` | Сопоставление событий с эталоном (precision/recall/F1), метрики отслеживания, IDF1 |

## Принципы

1. **Тяжёлое отдельно от лёгкого.** Инференс кэшируется; аналитику можно пересчитывать без GPU.
2. **Неизвестное остаётся неизвестным.** Нет калибровки — нет метров, а не нули. Мяч не виден — исход броска `unknown`, а не промах.
3. **Кластер ≠ команда.** Внутри прохода работают номера кластеров; названия команд применяются в самом конце, когда есть данные (номера и составы).
4. **Трек ≠ игрок.** Статистика по трекам сохраняется отдельно, объединение в игроков — по паре (команда, номер).
5. **Автоматика отделена от оценки.** Результаты программы сохраняются со статусом `automatic`; ручная разметка используется отдельно как ground truth и не меняет исходные файлы.

## Сменные компоненты

| Что | Значения | Где задаётся |
|---|---|---|
| Трекер | `bytetrack` (по умолчанию), `sam2` | `tracker` в конфигурации, выпадающий список в интерфейсе |
| Понижение размерности для команд | `pca` (по умолчанию), `umap` | `team_reducer` |
| Чтение номеров | `auto`, `smolvlm`, `resnet` | `number_reader`, веса в `number_weights` |
| Детектор | `roboflow` (локально), `roboflow_api`, `yolo`, `replay` | `backend` |
| Эмбеддинг формы | `auto` (SigLIP + цвет), `siglip`, `color` | `team_embedder` |

SAM2 отслеживает игроков в процессе восприятия и кладёт идентификаторы в поле
`track` кэша. Приложение видит их через `CachedPerception.provides_tracks` и
подставляет `ProvidedTracks` вместо ByteTrack; при отсутствии треков молча
возвращается к ByteTrack и пишет предупреждение в отчёт.
